# 简单 PRD：B站自动投稿工具（biliup-hub）

> 档位：**简单 PRD（默认档）** — 产品目标 + 用户故事 + 需求池(P0/P1/P2) + UI 设计稿 + 待确认问题
> 不含竞品 / 市场分析。事实来源：`视频发布规则.md`（现有手动流程）。

## 1. 项目信息

- **Language**：中文
- **Programming Language / 技术栈**：Electron 主进程 `main.js` 通过 `CHILDREN` 拉起子服务（`server.js` 监听 `localhost:3600`），`biliup-hub/lib` 用 Node `child_process` 调 `biliup.exe` 重写编排逻辑；前端为**原生 HTML/CSS/JS**（macos 玻璃拟态视觉，复用 `shared/status-luxe`）。**非 Vite/React/MUI**。
- **Project Name**：`biliup_hub`
- **原始需求复述**：在 tools-hub 工具箱新增第三个工具「B站自动投稿」，把本地视频按既定规则程序化投到 B站（UID 236743002 / Lk-转折点），覆盖上传 → 封面抽帧 → AIGC 头注入 → 合集后置 → 评论置顶 → 立即/定时发布全流程。v1 仅做手动触发，不复用 `D:\biliupR` 的 `.ps1/.bat`，配置全 UI 可编辑、不硬编码 `D:\` 路径。

## 2. 产品目标

将现有手动投稿流程（视频发布规则.md）固化为「选视频 → 填标签 → 选发布模式 → 一键投稿」的可编辑本地工具，自动完成上传、抽封面、注入 AIGC 合规头、合集后置、置顶评论等全链路，屏蔽 biliup-rs 的诸多坑点（--extra-fields 失效、合集接口被忽略、多行简介、索引延迟），让 UP 主无需记忆命令行即可稳定投稿，显著降低出错率与重复劳动。

## 3. 用户故事

- 作为 UP 主，我想选一个本地视频点一下就自动投稿并加合集，以免手动操作多个步骤容易出错。
- 作为 UP 主，我想在发布前指定「立即发布」或「定时发布(dtime)」，以便配合内容排期。
- 作为 UP 主，我想在 UI 直接编辑分区/合集/版权/简介/评论/AIGC 等固定参数，以免改批处理脚本。
- 作为 UP 主，我想看到上传进度与失败原因（重试耗尽 / 合集 -404 / Cookie 过期），以便判断是否需要重试。
- 作为维护者，我想把 cookies 路径与 biliup.exe 路径配置化而非写死 `D:\`，以便换机器或账号时零改造。

## 4. 需求池

### P0（v1 必须有）
- **[P0-1] 手动选视频执行全流程**：选本地 mp4 文件（或 `E:\素材\` 下某文件夹），执行：上传 → 抽第 1 秒封面 → 注入 AIGC 头 → 投稿成功后代加合集 → 置顶固定评论。
- **[P0-2] 固定投稿参数 UI 可编辑（默认带值）**：tid=17（游戏→单机游戏）、tag（动态传入，逗号分隔）、season_id=6918057（感动常在）、copyright=1（自制）、no_reprint=1（禁止转载）、line=bda2（B站直传）、cover=自动抽帧、标题=文件名去扩展名、简介=固定 4 行、自动评论=`老规矩！！！三连后关注私信自动回复下载方式`。
- **[P0-3] AIGC 头注入**：投稿元数据注入 YAML front-matter（Label=1、ContentProducer/ProduceID/ReservedCode1/ContentPropagator/PropagateID/ReservedCode2），满足合规标识。
- **[P0-4] 合集后置**：投稿成功后**独立 API** 后置添加 ——
  `POST https://member.bilibili.com/x2/creative/web/season/section/episodes/add`，参数 `sectionId=7630305`（注意：非 season_id；season_id 6918057 对应 sectionId 7630305）、`episodes=[{aid,cid,title,charging_pay:0}]`，需 `csrf`（cookies.json 的 `bili_jct`）+ 完整 Cookie（含 `SESSDATA`）。
- **[P0-5] 评论置顶**：上传完成后自动发布固定评论并置顶。
- **[P0-6] 封面抽帧**：用 ffmpeg 抽视频第 1 秒作为封面（来源见待确认 Q1）。
- **[P0-7] 发布模式**：「立即发布」（默认）/「指定时间发布」（经 `--dtime` Unix 时间戳传入）；发布前需二次确认弹窗询问模式。
- **[P0-8] 复现已知坑（变通必须实现，否则功能失效）**：
  1. `biliup-rs v1.2.1` 的 `--extra-fields` 在 subprocess 列表模式不生效 → 把完整命令写进**临时脚本文件**再调起（bat 用 `""` 转义双引号；ps1 用 `` ` `` 转义；ps1 必须 `utf-8-sig` 编码、头部 `@chcp 65001` 强制 UTF-8）。
  2. 合集 `season_id` 在 App 投稿接口被忽略 → 用 P0-4 后置 API。
  3. 简介多行：bat 无法嵌换行（`^` 吞换行）→ 用 ps1，`desc` 换行用 `` `n ``，文件 `utf-8-sig`。
  4. 上传后 B站 API 可能延迟索引（返回 -404）→ `get_video_info` 最多重试 20 次、每次间隔 10 秒（约 3 分钟）确保合集添加成功。

### P1（v1 宜有）
- **[P1-1]** cookies.json 路径可配置（默认 `D:\biliupR\cookies.json`）、biliup.exe 路径可配置（默认 `D:\biliupR\biliup.exe`）、ffmpeg 路径可配置。
- **[P1-2]** 上传进度 / 当前状态展示，接入 `status-luxe` 状态胶囊（空闲 / 上传中 / 合集后置中 / 成功 / 失败）。
- **[P1-3]** 失败重试与可读错误提示（合集 -404 重试、csrf 缺失、Cookie 过期、合集添加失败等分类提示）。
- **[P1-4]** 素材文件夹浏览选择（`E:\素材\` 内文件夹 → 自动取该文件夹内视频 + 用文件夹名匹配编号）。

### P2（后续版本）
- **[P2-1]** 9:10 每日自动扫描素材文件夹自动投稿。
- **[P2-2]** 批量投稿（多视频队列）。
- **[P2-3]** 多账号（多 cookies 切换）。

## 5. UI 设计稿（biliup-hub/public）

保持与网盘/金山前端一致的 macos 玻璃拟态视觉，复用 `shared/status-luxe`（需复制一份到 `biliup-hub/public` 并纳入 `scripts/sync-status-luxe.js` 同步与 `verify-status-luxe-sync.js` 门禁校验）。

```
┌──────────────────────────────────────────────────────────────────┐
│  B站自动投稿                                  [状态胶囊: 空闲]     │ ← 顶部标题 + status-luxe
├───────────────────────┬──────────────────────┬────────────────────┤
│ 选择视频 / 文件夹     │ 标签输入              │ 投稿参数(可折叠)   │
│ [浏览] 选 mp4 文件    │ [辐射4,单机游戏,RPG]  │ ▸ tid: 17          │
│ 或 [E:\素材\] 文件夹   ├──────────────────────┤ ▸ season: 6918057  │
│ ────────────────      │ 发布模式              │ ▸ 版权/转载:1/1    │
│ 预览标题:             │ (●) 立即发布          │ ▸ 简介(固定4行)    │
│ 【游戏252】潜水员戴夫  │ ( ) 定时发布          │ ▸ 评论(置顶)       │
│  官方中文+全DLC...     │   [ dtime 时间选择 ]  │ ▸ AIGC 头          │
│                       │                      │ (展开后可编辑)     │
├───────────────────────┴──────────────────────┴────────────────────┤
│  [ 🚀 投稿 ]                                                    │ ← 底部按钮(发布前二次确认)
│  ┌─ 进度日志 ─────────────────────────────────────────────────┐ │
│  │ > 抽封面帧1 ... ok                                          │ │
│  │ > 注入 AIGC 头 ... ok                                        │ │
│  │ > 上传中 62% ...                                             │ │
│  │ > 合集后置重试 3/20 (-404) ...                               │ │
│  └────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

**布局说明**
- **顶部**：标题「B站自动投稿」+ `status-luxe` 状态胶囊（空闲 → 上传中 → 合集后置中 → 成功/失败）。
- **主体三栏**：
  - 左 = 选择视频/文件夹 + 文件名预览即标题（标题规则：mp4 去扩展名，命名须符合 `【游戏编号】游戏名 版本描述 免费学习版下载.mp4`，编号与文件夹一致）。
  - 中 = 标签输入（逗号分隔）+ 发布模式（立即 / 定时带时间选择器；点「投稿」触发二次确认弹窗确认模式）。
  - 右 = 可折叠「投稿参数」面板，展示/编辑 tid / season / 版权 / 转载 / 简介 / 评论 / AIGC。
- **底部**：「投稿」按钮（发布前二次确认）+ 进度日志区（实时回显 child_process 输出与重试状态）。

## 6. 待确认问题（需主理人 / 用户拍板）

1. **ffmpeg 来源与路径策略**：是否随 biliup.exe 自带？若无，安装路径默认值与可配置项如何处理，抽帧命令（`-ss 00:00:01 -vframes 1`）如何拼。
2. **biliup.exe 版本锁定**：是否锁 `v1.2.1`（坑点基于该版）？升级后 `--extra-fields` / 合集 API 行为是否变化需回归；版本号是否 UI 可显。
3. **AIGC 头注入策略**：是否每个视频都注入（固定 Label=1）？`ReservedCode1/2` 等长 base64 是否每次相同、是否需在 UI 可编辑。
4. **单视频 vs 批量边界**：v1 是否严格单视频（一次一个卡片提交），还是允许文件夹内多视频一次排队（触及 P2-2 边界，需明确划线）。
5. **合集后置 Cookie 完整性**：当前 cookies.json 是否含足够权限（`SESSDATA` + `bili_jct`），过期刷新流程由谁（用户手动 / 工具提示）触发。
