# 网盘转存中转台 · 部署指南（给朋友版）

> 适用：**另一台电脑本机本地使用**。服务绑 `127.0.0.1`，仅本机浏览器能访问，天然不暴露，最安全。

## 一、最短路径（推荐，双击即可）

1. 拿到代码：
   - Git：`git clone <仓库地址>` 然后 `cd netdisk-hub`
   - 或直接把整个 `netdisk-hub` 文件夹拷过来
2. **双击 `setup.bat`** —— 自动：检测 Node → 装 npm 依赖 → 装 Chromium 内核 → 生成 `.env` 模板 → 启动服务（新窗口）
3. 用记事本打开 `.env`，填入你在百度开放平台申请的 `BAIDU_CLIENT_ID` / `BAIDU_CLIENT_SECRET`（见第四节）
4. 浏览器打开 http://localhost:3000，点百度/夸克/迅雷「授权」扫码登录
5. 开始用

> 只有**填 .env** 和**扫码登录**两步必须手动，其余全自动。

## 二、setup.bat 自动做了什么

- 检测 Node：优先用 WorkBuddy 内置 Node，找不到则用系统 `node`，都没有则提示去装
- `npm install` 安装依赖
- `npx playwright install chromium` 装浏览器内核（夸克/迅雷授权页必须）
- 若没有 `.env`，复制 `.env.example` 生成
- 启动服务（后台最小化窗口）

## 三、手动安装（备选）

若不想用脚本：

```bash
npm install
npx playwright install chromium
cp .env.example .env   # 然后填百度凭证
npm start              # 或 node server.js
```

也可双击项目内 `启动面板.bat` 启动 tkinter 控制面板（无黑框后台运行）。

## 四、登录网盘（无需申请任何开发者应用）

百度 / 夸克 / 迅雷现在都走**网页登录**，不用去任何开放平台申请应用：

- **百度**：网页点「授权百度网盘」→ 弹出浏览器登录你的百度账号 → 自动保存登录态（走 Playwright 抓取登录 Cookie，转存鉴权靠此，不依赖 OAuth）。`.env` 里 `BAIDU_CLIENT_ID` / `BAIDU_CLIENT_SECRET` 是兼容遗留字段，**留默认占位也能用**；但若你从已配置机器复制了真实凭证，也完全支持。换机最省事的做法：直接把源机器整份 `.env` 复制过去（含百度私有凭证），不要只拿 `.env.example` 占位符。
- **夸克**：网页点「授权夸克网盘」→ 弹出浏览器扫码/登录 → 自动保存 Cookie。
- **迅雷**：网页点「授权迅雷网盘」→ 弹出浏览器登录 pan.xunlei.com → 登录态自动持久化。

### 转存目录：网页上选，选完记住（推荐）

每个网盘账号卡片上都有「📁 转存到（默认/已选）：<目录>」一行和「选择目录」按钮：

1. 点「选择目录」→ 弹出目录浏览器（面包屑 + 子文件夹列表）。
2. 层层进入，找到目标文件夹后点「选择此目录」。
3. 选择会**持久化到 `data/store.json`**，重启服务、刷新页面都在；之后所有转存自动进该目录，**不再需要改 `.env`**。
4. 想换目录：再点「选择目录」重新选即可。

> `.env` 里的 `BAIDU_APP_DIR` / `QUARK_FOLDER` 现在只是**未网页选目录时的回退默认值**，不是必须改的项。换机最稳的做法仍是：复制整份 `.env`（目录默认一致）+ 网页里再按需微调目录。

> 首次授权依赖 Playwright Chromium 内核（setup.bat 已自动安装）。若弹出登录页失败，手动 `npx playwright install chromium` 重试。

## 五、重新登录网盘

`data/` 不随代码走（隐私设计，已被 gitignore），换机器后需重新授权：

- 百度：网页 OAuth 授权
- 夸克 / 迅雷：本机浏览器扫码

## 六、注意事项

- 服务仅监听 `127.0.0.1:3000`，局域网 / 公网其他设备无法访问。
- 历史转存记录、网盘登录态都在本地 `data/`，**不跨机器**，换机器要重登（这是设计不是 bug）。
- 百度 OAuth 回调写死 `localhost:3000`；只有以后要「远程访问 / 公网部署」才需改。
- 无进程守护：服务崩溃会退出，需手动重启（双击 `setup.bat` 或 `启动面板.bat` 点启动即可）。

## 七、远程访问 / 公网部署（进阶，非默认）

若要跨网在另一台设备访问本机服务，**不要直接暴露 3000 端口**，否则等于把网盘 cookie 交出去。正确做法：

1. 用内网穿透（Cloudflare Tunnel / frp 等）暴露到公网域名
2. 配 HTTPS
3. **必须加访问认证**：在 `server.js` 加登录密码中间件，或前置带 Basic Auth 的反向代理（Caddy / Nginx）
4. 同步把 `.env` 里百度回调改为你的公网域名

> 不解决认证就暴露 = 任何人可触发转存并盗用你的网盘。本机本地用（默认）则无需上述步骤。

## 八、日常更新（多机同步）

项目在 GitHub 私有仓库，两台电脑改完都能同步，靠 Git 的 `push` / `pull`：

**改完代码的这台电脑：**
- 若让助手改功能：助手会直接 `commit + push`，你不用动
- 若你自己改了源码：在项目目录执行
  ```bash
  git add -A
  git commit -m "改了什么"
  git push
  ```

**另一台电脑拉取最新：**
- 当前 netdisk-hub 已并入 **tools-hub** 统一源码；日常更新统一由桌面壳 tools-hub 负责（工具箱内点「检测更新」自动升级），无需在本服务内单独更新
- 或命令行：`git pull`

> 注意：
> - `.env` 和 `data/` 不进 Git（隐私设计），各机本地独立、互不覆盖，换机仍需各自填凭证 / 扫码
> - 拉取后**重启服务**即生效（双击 `启动面板.bat` 点重启）；若作为 tools-hub 子服务运行，重启由工具箱统一管理
> - 网页右上角版本徽章仅展示版本（由工具箱统一管理），不再提供「检查更新 / 更新并重启」按钮
> - 若某台本地有未提交的修改，`git pull` 可能冲突，先 `git status` 看冲突文件处理即可
